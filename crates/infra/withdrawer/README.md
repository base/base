# Withdrawer configuration, RPC, transactions, and withdrawal proofs

`base-withdrawer` provides `WithdrawerArgs`, a clap parser, and `WithdrawerConfig`, its typed configuration. Conversion validates settings without deriving keys or accessing devices. The library also supplies signers, typed RPC clients, L1 transaction preparation and signing, withdrawal extraction, local proof verification, read-only decisions about a withdrawal's next step from onchain state, and verified proving-commitment selection. Submission is not implemented.

Supply `--l1-rpc-url`, `--withdrawal`, and exactly one signing source. `--private-key` accepts a 32-byte hex key, also available through `WITHDRAWER_PRIVATE_KEY`. `--mnemonic` accepts an English BIP-39 phrase as one quoted value or separate words, also available through `WITHDRAWER_MNEMONIC`. Conversion joins the words with single spaces and validates the phrase. `--ledger` is available only with the `ledger` Cargo feature. Mnemonic and Ledger sources use `--hd-path`, defaulting to `m/44'/60'/0'/0/0`. Paths must have at most 255 components. Each component must have an index between 0 and 2147483647, with or without a hardened suffix. Secrets have redacted debug output and parse errors. RPC URL parse errors retain the parse reason and flag name without the rejected value. `--hd-path` parse errors retain the flag name and a fixed reason without the rejected value. Other invalid-value errors retain declared flag names, but redact values and omit suggestions. A flag given with no value keeps clap's "a value is required" message. Unexpected-argument errors redact the entire token regardless of the signing source. `--version` prints the crate version. Prefer environment variables over argv to avoid exposing secrets in process listings.

`WithdrawalSigner::new(&SignerSource)` asynchronously creates a local signer or connects to a Ledger. Raw keys must be nonzero secp256k1 scalars. Mnemonics use standard BIP-39 with an empty passphrase and BIP-32 at the configured path. The signer implements `alloy_network::TxSigner<Signature>` for its address and transaction signing; `is_ledger()` identifies hardware signers. Debug output never includes signing secrets.

The optional `ledger` Cargo feature enables `alloy-signer-ledger` and the Ledger signing source. Connect and unlock the device and open its Ethereum app before construction. Ledger paths must have at most 10 components, the Ethereum app's limit. Ledger signatures must recover to the device's address. Legacy transactions are refused on chain IDs where the device's truncated EIP-155 parity cannot be decoded reliably, such as 111. Use EIP-1559 fees on those chains instead.

`--network` selects `base-mainnet` by default, or `base-sepolia`, `op-mainnet`, or `op-sepolia`. Each preset uses fault proofs and records its L1 chain ID: 1 for the mainnets and 11155111 for the Sepolia networks. For a custom network, omit `--network` and supply `--l2-rpc-url`, `--portal`, and either both `--dispute-game-factory` and `--anchor-state-registry`, or `--l2-output-oracle`. Addresses and withdrawal hashes require exact-length hex values. Custom contract addresses must not be zero. Custom networks have no expected L1 chain ID.

Fees default to automatic estimation. `--gas-price` selects legacy fees. EIP-1559 requires both `--max-fee-per-gas` and `--max-priority-fee-per-gas`. Fees are decimal wei and must fit `u128`. `--max-gas-price` caps the final legacy gas price and both EIP-1559 fees on every preparation, including automatic estimates. Fees above the cap return an error rather than being clamped. `--gas-limit` bypasses gas estimation and conflicts with `--gas-multiplier`, whose default is 1.0 and which must be finite and at least 1.0.

`--timeout` defaults to `10m`, `--max-retries` to 3, and `--retry-delay` to `2s`. Durations use humantime syntax and must be positive. At most 32 retries are allowed, and conversion rejects retry delays whose exponential backoff would overflow a Rust duration. `--dry-run` disables signing and submission in later layers.

`WithdrawalRpc::new(&WithdrawerConfig)` synchronously builds `l1` and `l2` alloy `RootProvider` clients with reqwest, regardless of other enabled alloy backends. Construction performs no network I/O. Only HTTP(S) is supported. Other URL schemes are rejected without exposing the endpoint. Each HTTP attempt, including direct provider reads, is bounded by `WithdrawalRpcTransport::REQUEST_TIMEOUT` (30 seconds), capped at half the configured `timeout` so a hung request can be retried before the operation deadline. Use standard `Provider` methods directly for contract calls, storage proofs, receipts, and pending nonces, such as `rpc.l1.get_transaction_count(address).pending().await`.

The transport retries connection failures, request timeouts, HTTP 429/5xx regardless of response body, and single JSON-RPC responses recognized as retryable by alloy, including rate limits and `header not found`. On successful HTTP responses, execution reverts are not retried, even when their reason mentions a rate limit. Batch responses preserve each item's outcome without retrying individual JSON-RPC errors. `max_retries` counts attempts after the first, with delays of `retry_delay`, twice that delay, and so on. This uses a small tower service because alloy's `RetryBackoffLayer` uses a fixed base delay. Requests, including whole batches on transport failures, are replayed unchanged. Use these clients for reads and already signed submissions, not non-idempotent RPC methods. Transport errors strip URLs and HTTP bodies while retaining safe source errors. HTTP client tracing is disabled to keep endpoint credentials out of spans. JSON-RPC envelope parse failures in `WithdrawalRpcTransport` retain only the error category and location. Alloy's typed-result decoding errors include the server's response content, as do JSON-RPC error messages.

`PreparedWithdrawalTransaction::prepare(&config, &rpc, sender, target, calldata)` prepares a zero-value L1 call without constructing or accessing a signer. It reads the L1 chain ID and returns `L1ChainMismatch` before any other request when it differs from the network's expected L1 chain ID; custom networks skip this check. It fetches the sender's pending nonce on every call, so already pending transactions count toward the nonce. Preparation does not reserve nonces. Callers must serialize preparation and submission for a sender. Explicit fees are used unchanged. Automatic fees use alloy's `Provider::estimate_eip1559_fees` when the latest block has a base fee, or `Provider::get_gas_price` for a legacy transaction when it does not. A missing latest block is an error, not a reason to select legacy fees. The complete preparation is bounded by `rpc.timeout`. RPC errors pass through `WithdrawalRpcTransport::redact` before being wrapped with their safe sources in `WithdrawalTransactionError`.

Without `gas_limit`, estimation uses the same sender, target, calldata, chain ID, value, and fees as the final call, but omits the nonce. The gas estimate is multiplied by `gas_multiplier` using `f64` arithmetic and rounded up. Non-finite results or values outside the `u64` range are errors. The prepared `sender()` and alloy `TypedTransaction` from `transaction()` are read-only so the checked fees and estimation sender cannot change before signing. `maximum_gas_cost()` returns the gas limit times the maximum per-gas fee in `U256` wei. A later flow layer can inspect these without signing for a dry run. The preparation and signing methods do not interpret `dry_run`; that decision belongs to the flow layer.

`prepared.sign(&signer)` rejects a signer whose address differs from the prepared sender. It signs with `WithdrawalSigner`, including its Ledger policy checks, and returns an alloy `TxEnvelope` ready for `rpc.broadcast(&envelope)`. Signing does not fetch a new nonce, change the prepared call, or submit it.

`WithdrawalRpc::l2` uses `base_common_network::Base`, so provider receipts include deposit transactions of type `0x7e`. Pass an L2 receipt to `Withdrawal::from_receipt` to extract every `MessagePassed` event from `Predeploys::L2_TO_L1_MESSAGE_PASSER` in log order. Other emitters and event signatures are ignored. Missing withdrawals, missing block numbers, malformed events, and emitted hashes that disagree with the decoded fields return typed `WithdrawalError` variants. Each withdrawal contains a sol `WithdrawalTransaction` and its `u64` inclusion block number. `hash()` computes the ABI field commitment; `slot()` derives its `sentMessages` mapping key.

`Withdrawal::verify_proof` takes an L2 RPC header, an EIP-1186 account proof, and an onchain output root claim. It recomputes the header hash locally, authenticates the message passer account against the header state root, and verifies exactly one storage proof for the withdrawal slot with value one. The output commitment uses `base_protocol::OutputRoot` and must match the claim. Success returns `VerifiedWithdrawalProof` with the sol `OutputRootProof` and storage proof nodes for the portal's `proveWithdrawalTransaction` arguments. Trie and event-decoding errors retain their sources. Storage proofs are accepted with inline nodes either omitted, as Geth returns them, or kept as separate elements, as reth returns them; the returned nodes always keep them separate. Verification does not fetch data, establish the claim's validity or finality, or submit transactions. Dispute games are permissionless, so callers must check that the game is proper, respected, and not resolved as `CHALLENGER_WINS` before relying on its claim.

`broadcast(&TxEnvelope)` submits the signed L1 transaction without signing or changing its bytes, within the configured `timeout` across attempts, backoff, and reconciliation. It returns the envelope's local transaction hash, including when the node reports an already-known transaction. For other JSON-RPC rejections, it looks up that local hash once: if the node knows the transaction, it warns and returns success; if the lookup misses or fails, it returns the original rejection as the source. This handles a lost submission response followed by a retry rejected after inclusion. Transport and deserialization failures do not trigger reconciliation. A mismatched hash or malformed result inside a successful JSON-RPC response produces a warning, not a submission failure. A non-JSON-RPC response is still an error. No `broadcast` error, including `Timeout`, `Request`, and transport failures, means "not submitted": an earlier attempt may have been accepted with its response lost. Check the envelope's `tx_hash()`, for example with `wait_for_receipt`, before re-signing or resubmitting. `wait_for_receipt(hash)` polls L1 every `WithdrawalRpc::RECEIPT_POLL_INTERVAL`, currently two seconds, within the configured `timeout`, continuing after retryable failures even when a poll exhausts its transport retries. Deterministic errors return immediately. It returns `WithdrawalRpcError::Reverted` for status zero and `WithdrawalRpcError::Timeout` when either operation's deadline expires.

## Prove/finalize flow

`Withdrawer::status` performs only reads against the latest mined L1 state.

`WithdrawalStatus` separates onchain decisions from transaction submission. `Finalized` does nothing, `Prove` requires a new proof, `Finalize` permits execution, and `Paused` waits for the anchor state registry (fault proofs) or legacy portal (output oracle) to be unpaused before proving or finalizing. `NotReady` reports an earliest known L1 timestamp with a flag for an unresolved game. The game must resolve before its finality delay can start, so that timestamp is not a promise of readiness.

Fault-proof state uses `provenWithdrawals(hash, signer_address)`. While the anchor state registry or legacy portal is paused, withdrawals wait without replacing proofs. When the registry is unpaused, blacklisted, retired, improper, unrespected, and challenger-winning games invalidate a fault proof. In-progress games retain their proofs but cannot finalize. Legacy proofs are invalidated when their stored output root differs from the oracle, or when the stored output's lookup reverts. Other legacy RPC errors fail without submitting.

Fault-proof finalization requires proof maturity and ASR game finality, followed by the portal's authoritative `checkWithdrawal` call. Legacy finalization checks the proof and output ages against the latest L1 timestamp, not the local clock or L2 time. Both apply the portal's strict timestamp boundary.

Flow RPC errors use `WithdrawalRpcTransport::redact_diagnostic` to remove server-supplied messages and data that might echo credentials. They retain the typed transport source and JSON-RPC error code. Retry classification runs on the raw error. Execution-revert classification runs on the redacted error and relies on redaction preserving the code and the "execution reverted" marker. Contract and withdrawal event ABI decode errors identify the call or event and error kind without response data. At the flow boundary, account and storage proof errors replace value-mismatch payloads with their error kind and retain safe proof errors as sources. The same redaction applies to warnings for skipped games.

Proving walks factory entries backwards from `gameCount() - 1`. It fetches the withdrawal's L2 block timestamp once and stops the walk at the first game of any type created before that timestamp. That game and all older games predate the withdrawal and cannot honestly cover it. The flow considers games of any type, including earlier types that were respected when the games were created. Each covering game costs three contract reads during the walk: `gameAtIndex`, `extraData` for its claimed L2 block, and `isGameFinalized`. The flow skips malformed or overflowing block numbers before the finality read. It also skips non-covering games, since games can be created out of L2 block order. Eligibility checks and the `rootClaim` read are deferred until a candidate is about to be verified. This applies to finalized games too, since finality alone does not imply eligibility. Ineligible candidates are skipped without a warning.

The walk tries to verify covering, eligible games that the `AnchorStateRegistry` reports as finalized, returning the newest one that verifies. Only proof maturity remains for those games. It saves non-finalized candidates as their factory index, proxy, and claimed L2 block without reading eligibility or `rootClaim`. If no finalized game verifies before the timestamp cutoff or the end of the factory, it tries the saved candidates from oldest to newest and returns the first that verifies, since the oldest game should resolve first.

Some L2 RPCs, including the default `base-mainnet` endpoint, only serve recent state. Once transport retries are exhausted, the first RPC failure fetching a candidate's L2 header or `eth_getProof` makes the flow assume historical state is unavailable. It stops the backward walk or abandons the oldest-first order and tries the remaining untried saved candidates from newest to oldest. It returns the first that verifies. A second proof RPC failure stops selection immediately with that error, so at most two candidates incur RPC stalls and their transport retries. If the fallback exhausts its candidates, the first RPC error is returned.

Games with fewer than 32 bytes of `extraData`, block numbers exceeding `u64`, unavailable claimed L2 blocks, or failed local proof verification are skipped with a warning containing the game index, proxy, and redacted reason. These non-RPC failures do not change the selection order, including during the newest-first fallback. Proof RPC failures also warn with the game index, proxy, and redacted error. If no candidate verifies and no proof RPC failure occurred, the flow returns `WithdrawerError::NoCoverage`. Errors from factory, registry, and game contract reads and contract-response decoding errors still stop selection. Legacy selection returns `WithdrawerError::NoCoverage` when no published commitment covers the withdrawal.

Before selecting a commitment, the flow fetches its L2 header and message passer `eth_getProof`, then calls `Withdrawal::verify_proof` against the published root. Fault-proof games that fail verification do not prevent trying the next candidate in the selection order; legacy verification failures return an error.

# Withdrawer configuration, signing, and RPC

`base-withdrawer` provides `WithdrawerArgs`, a clap parser, and `WithdrawerConfig`, its typed configuration. Conversion validates settings without deriving keys or accessing devices. The library also supplies signers and typed RPC clients. Proof construction and the prove/finalize flow are not implemented.

Supply `--l1-rpc-url`, `--withdrawal`, and exactly one signing source. `--private-key` accepts a 32-byte hex key, also available through `WITHDRAWER_PRIVATE_KEY`. `--mnemonic` accepts an English BIP-39 phrase as one quoted value or separate words, also available through `WITHDRAWER_MNEMONIC`. Conversion joins the words with single spaces and validates the phrase. `--ledger` is available only with the `ledger` Cargo feature. Mnemonic and Ledger sources use `--hd-path`, defaulting to `m/44'/60'/0'/0/0`. Paths must have at most 255 components. Each component must have an index between 0 and 2147483647, with or without a hardened suffix. Secrets have redacted debug output and parse errors. Prefer environment variables over argv to avoid exposing secrets in process listings.

`WithdrawalSigner::new(&SignerSource)` asynchronously creates a local signer or connects to a Ledger. Raw keys must be nonzero secp256k1 scalars. Mnemonics use standard BIP-39 with an empty passphrase and BIP-32 at the configured path. The signer implements `alloy_network::TxSigner<Signature>` for its address and transaction signing; `is_ledger()` identifies hardware signers. Debug output never includes signing secrets.

The optional `ledger` Cargo feature enables `alloy-signer-ledger` and the Ledger signing source. Connect and unlock the device and open its Ethereum app before construction. Ledger paths must have at most 10 components, the Ethereum app's limit. Ledger signatures must recover to the device's address. Legacy transactions are refused on chain IDs where the device's truncated EIP-155 parity cannot be decoded reliably, such as 111. Use EIP-1559 fees on those chains instead.

`--network` selects `base-mainnet` by default, or `base-sepolia`, `op-mainnet`, or `op-sepolia`. Each preset uses fault proofs. For a custom network, omit `--network` and supply `--l2-rpc-url`, `--portal`, and either both `--dispute-game-factory` and `--anchor-state-registry`, or `--l2-output-oracle`. Addresses and withdrawal hashes require exact-length hex values. Custom contract addresses must not be zero.

Fees default to automatic estimation. `--gas-price` selects legacy fees. EIP-1559 requires both `--max-fee-per-gas` and `--max-priority-fee-per-gas`. Fees are decimal wei and must fit `u128`. `--max-gas-price` optionally caps explicit fees and later automatic estimation. `--gas-limit` overrides estimation and conflicts with `--gas-multiplier`, whose default is 1.0 and which must be finite and at least 1.0.

`--timeout` defaults to `10m`, `--max-retries` to 3, and `--retry-delay` to `2s`. Durations use humantime syntax and must be positive. At most 32 retries are allowed, and conversion rejects retry delays whose exponential backoff would overflow a Rust duration. `--dry-run` disables signing and submission in later layers.

`WithdrawalRpc::new(&WithdrawerConfig)` builds `l1` and `l2` alloy `RootProvider` clients with reqwest, regardless of other enabled alloy backends. Only HTTP(S) is supported. Other URL schemes are rejected without exposing the endpoint. Each HTTP attempt is bounded by the configured `timeout`, including direct provider reads. Use standard `Provider` methods directly for contract calls, storage proofs, receipts, and pending nonces, such as `rpc.l1.get_transaction_count(address).pending().await`.

The transport retries connection failures, request timeouts, HTTP 429/5xx, and single JSON-RPC responses recognized as retryable by alloy, including rate limits and `header not found`. Execution reverts are not retried, even when their reason mentions a rate limit. Batch responses preserve each item's outcome without retrying individual JSON-RPC errors. `max_retries` counts attempts after the first, with delays of `retry_delay`, twice that delay, and so on. This uses a small tower layer because alloy's `RetryBackoffLayer` uses a fixed base delay. Requests, including whole batches on transport failures, are replayed unchanged. Use these clients for reads and already signed submissions, not non-idempotent RPC methods. Transport errors strip URLs and HTTP bodies while retaining safe source errors. Internal transport tracing is disabled because alloy records full endpoint URLs in debug spans.

`broadcast(&TxEnvelope)` submits the signed L1 transaction without signing or changing its bytes, within the configured `timeout` across attempts, backoff, and reconciliation. It returns the envelope's local transaction hash, including when the node reports an already-known transaction. For other JSON-RPC rejections, it looks up that local hash once: if the node knows the transaction, it warns and returns success; if the lookup misses or fails, it returns the original rejection as the source. This handles a lost submission response followed by a retry rejected after inclusion. Transport and deserialization failures do not trigger reconciliation. A mismatched hash or malformed result inside a successful JSON-RPC response produces a warning, not a submission failure. A non-JSON-RPC response is still an error. `wait_for_receipt(hash)` polls L1 every `WithdrawalRpc::RECEIPT_POLL_INTERVAL`, currently two seconds, within the configured `timeout`. It returns `WithdrawalRpcError::Reverted` for status zero and `WithdrawalRpcError::Timeout` when either operation's deadline expires.
